# openSEO 系統架構與設計哲學 (System Architecture & Design Philosophy)

本文檔詳細記錄 **openSEO** 的核心設計哲學、演算法模型與資料庫拓撲結構。

---

## 1. 核心哲學：確定性 vs 隨機生成 (Deterministic vs Hallucination)

傳統 AI SEO 工具最大的問題在於**隨機性 (Non-determinism) 與偽指標**：
- 盲目設定每篇文章「必須包含 3% 關鍵詞密度」；
- 憑空捏造無意義的 300~500 字廢話段落；
- 每天丟出數十個互相衝突的「優化建議」，令工程與營運團隊疲於奔命卻見不到實質排名增長。

**openSEO 堅持確定性 (Deterministic Engineering)**：
1. **單一北極星行動 (#1 Priority Action)**：
   每天只推薦一個全站 ROI 最高的行動。當站點平穩、數據指標處於健康區間時，系統會誠實輸出 `DO_NOTHING`，嚴禁為了刷存在感而隨意發布無效修改指令。
2. **防震盪冷卻防護 (Cooldown Discipline)**：
   搜尋引擎爬蟲重新索引與權重重算通常需要 3~7 天時間。openSEO 內建冷卻映射表，在指定時間窗口內強制鎖定已修改的頁面，防止前腳剛改完標題、後腳又推倒重來的左右互搏現象。
3. **科學實驗假說體系 (Experiment Baseline Discipline)**：
   每一次行動都必須自動編譯出完整的實驗假說卡片：
   - **Hypothesis (假說)**：本次修改預期帶來的具體數值變化。
   - **Primary Metric (核心指標)**：主要驗證排位或 CTR。
   - **Secondary Metric (輔助指標)**：自然曝光量的放大。
   - **Guardrail Metric (護欄指標)**：監控是否有其他周邊頁面遭到權重稀釋。

## 2. 關鍵詞資產層三大病症 (The Three Critical Keyword Diseases)

專業 SEO 管理的核心不是單純看「有多少個頁面」，而是掌握「**關鍵詞 ➔ 目標落地頁 (Term ➔ Target Landing Page)**」的對應關係。

```
              ┌─────────────────────────────┐
              │   搜尋引擎中的真人搜尋意圖     │
              └──────────────┬──────────────┘
                             │
            ┌────────────────┼────────────────┐
            ▼                ▼                ▼
       【 1. GAP 】   【 2. 自相殘殺 】   【 3. 錯配 】
    有搜尋量但全站無   兩頁搶同詞導致權重   排上去的頁面不是
    任何專屬頁面負責   分散、互相拉低排位   預期想轉化的落地頁
```

### ① GAP (有需求無頁面)
- **症狀**：GSC 出現明顯的搜尋意圖或外部詞庫存在高頻搜尋量，但資料庫中 `target_url IS NULL`。
- **後果**：使用者搜尋後在搜尋結果找不到本站，流量全數流失至競品。
- **解法**：系統自動推薦建立專屬中層 Hub、主題指南或聚合分類頁。

### ② 自相殘殺 (Cannibalization)
- **症狀**：多個 URL 針對完全相同的查詢詞競爭，且在 GSC 中交替獲得點擊。
- **後果**：搜尋引擎判定內部內容重複，降低整體頁面權威度。
- **解法**：透過 Canonical 標籤收攏、重構內部鏈接錨文本，或透過 301 重定向合流。

### ③ 錯配 (Misalignment)
- **症狀**：搜尋引擎展示的頁面（`best_url`）並非我們期望轉化的主力落地頁（`target_url`）。
- **後果**：進站跳出率極高，無法促成轉換。
- **解法**：強化主力落地頁的 H1、Title 與站內入鏈權重，削弱次要頁面的非意圖覆蓋。

## 3. 五維健康度成熟度矩陣 (5-Pillar SEO Readiness Matrix)

openSEO 將搜尋引擎優化拆解為 5 個不可逾越的實體維度：

1. **Technical SEO (技術基石)**：
   - 嚴格檢查 Canonical URL 規範化（杜絕斜線與大小寫重複內容）；
   - Sitemap 分片生成機制（符合 50,000 URLs /  shard 國際標準）；
   - JSON-LD 結構化資料（Product, BreadcrumbList, Organization 等）。
2. **Content & Thin Content (內容品質)**：
   - 杜絕零庫存死品與軟 404 頁面輸送；
   - 規格表格化（直出原生 `<table>`，提升資訊密度）。
3. **Internal Linking (拓撲權重)**：
   - 孤島頁面 (Orphan Pages) 即時偵測；
   - 類別到商品、商品到相關商品的權重網絡分配。
4. **Coverage & Indexing (索引真實覆蓋)**：
   - 實施分層抽樣，不盲目追求全量爬取；
   - 維護高索引率（已收錄 / 已提交 >= 85%）。
5. **GSC Data Loop (真實數據迴路)**：
   - 雙軌定時拉取大盤 (Aggregate) 與查詢 (Query) 明細；
   - 區分「從未同步」、「同步失敗」與「Google 隱私匿名化」，拒絕假零顯示。
